# DIGEST 1 — NAMING & UNIVERS MINÉRAL

Logique générale : une **gradation sémantique** (échelle de prestige, de l'infime au monumental) + la recherche d'un mot juste pour nommer un « streak » sans le mot anglais standard.

## A. Petites entités (du grain au caillou)
- **Pebble** — « petit caillou arrondi et lisse (usé par l'eau) ». Terme fondateur (un souvenir = un pebble). Doux, organique.
- **Stone** — générique, « on peut la tenir en main ». Neutre.
- **Rock** — plus brut, dur, ancré.
- **Cobble / Cobblestone** — plus gros, le « pavé » naturel des lits de rivières.
- **Gravel** — « gravier », collectif de petits fragments.
- **Shingle** — galets plats de plage.
- Échelle : **Gravel < Pebble < Stone < Cobble < Boulder < Monolith**.

## B. Grandes entités
- **Boulder** — « très gros rocher détaché, souvent arrondi » (rocher solitaire).
- **Rock face / Crag** — paroi/éperon escarpé.
- **Monolith** — bloc massif d'un seul tenant. Ambiance « impressionnant / SF ». Retenu comme sommet de hiérarchie (« puissance et unité »).
- **Slab** — « dalle » large et plate.
- **Menhir / Standing stone** — pierre dressée par l'homme.

## C. Empilements (l'arbitrage central cairn vs pile vs heap)
- **Cairn** — tas de pierres **volontairement empilées** (sommet, chemin de rando, monument). « Spirituel / Pratique ». **L'intentionnalité + la dimension repère/mémoriel** le distinguent → pertinent pour Pebbles (piles de souvenirs = cairns).
- **Pile** — générique/utilitaire, « tas sans forme » (chantier, jardin). **Rejeté : trop utilitaire, sans âme.**
- **Heap** — comme pile mais désordonné/négligé (décombres). **Rejeté : connotation négative (ruines).**
- **Mound** — monticule (terre + pierres), arrondi/ancien.
- **Stack** — pierres plates posées soigneusement.
- Synthèse : **Cairn = spirituel/pratique ; Pile = neutre ; Heap = désordonné.**

## D. Grandes structures
- **Dolmen / Quoit** — structure funéraire (dalle sur pierres verticales).
- **Megalith** — pierres géantes (Stonehenge).
- **Scree / Talus** — « pierrier » au pied d'une falaise.
- **Barrow / Tumulus** — monticule recouvrant une sépulture.
- **Arbitrage « dolmen »** : scientifiquement funéraire, mais surtout *« Si vous dites dolmen à un anglophone, il visualisera immédiatement Astérix ou un site préhistorique… préférez "a stone table-like structure". »* → **double écueil funéraire + Astérix → disqualifié** comme nom de marque. Alternatives : stone table, megalithic structure, cromlech, quoit ; structures naturelles : balanced/balancing rock, perched boulder, tor.
- **Arbitrage « menhir »** : existe en anglais mais « très spécialiste / européen », emprunté au breton. Alternative naturelle : **standing stone** (« 99 % des anglophones »). Nuance de marque : *« menhir évoque Obélix et la Bretagne ; standing stone évoque les îles Britanniques ou Outlander. »* Voisins : monolith (taille), obelisk (pointe pyramidale), stele/stèle (inscriptions, souvent funéraire), orthostat (les « pieds » d'un dolmen).

## E. Minéraux précieux / « belles pierres »
Base : **gem/gemstone**, **jewel** (pierre montée), **nugget** (pépite brute), **bead** (perle percée), **crystal** (structure géométrique).
Gradation cherchée **paillette → pépite → monolithe** :
- **Paillette → Speck** (« petit point brillant, étincelle de matière ») ou **Flake** (« lamelle/éclat plat »). *Glitter* écarté (« trop artificiel »).
- **Pépite → Nugget** — « le mot parfait… ce côté trésor brut » (pas d'alternative aussi forte).
- **Monolithe → Monolith of Pride** — registre majestueux ; variantes Pillar of Pride, Stele of Pride.
- Poétiques : **The Shard** (« éclat/tesson, plus tranchant »), **The Slab**.
- Gradation retenue : **The Speck → The Nugget → … → The Monolith.**

## F. Lieux & passages
- **Quarry** (carrière), **Gravel pit** (gravière), **Path/Pathway** (chemin aménagé), **Trail** (sentier sauvage), **Cliff** (falaise), **Outcrop** (affleurement — proposé aussi comme nom de grade : « la pierre qui sort de terre »), **Bedrock** (socle).

## G. Le cas « ricochet » / streak (recherche la plus poussée)
Problème : renommer le streak en évoquant le **ricochet** (pierre qui rebondit sur l'eau), mais faux-ami.
- *« streak évoque une série ininterrompue ; skip signifie sauter/omettre. C'est le contraire absolu. »*
- *« en anglais, un ricochet est souvent perçu comme un accident… »* Le terme jeu correct = **to skip stones / stone skipping** (le galet idéal = **skipping stone**), pas « ricochet » (balistique).
- Candidats successifs : **A Run** (« a run of luck »), **A Chain**, **The Roll** (« on a roll »), **A Succession** (« lignée »), **The Momentum**.
- Puis registre ricochet : **The Skipper** (« le ricocheur »), **The Stone-Skip**, **The Skimmer** (« to skim = la pierre qui rase l'eau sans couler ; la légèreté absolue ») — **candidat le plus recommandé par Gemini** — , **The Series of Skips**.
- Puis Alexis propose **« bounce »**. Analyse Gemini : court, clair, positif, MAIS image du ballon (« balle de tennis/basket ») + **manque de matière** (« Speck/Nugget/Monolith décrivent des **objets** ; Bounce décrit une **action** »). Alternatives « premium » : **The Bound** (« cousin plus noble »), **The Skip**, **The Outcrop** (100 % minéral).
- **Aucune décision finale n'est consignée dans le fichier.** Gemini laisse deux hiérarchies : `Speck → Nugget → The Skip → Monolith` (esprit ricochet) ou `Speck → Nugget → The Bounce → Monolith` (énergie). → **NB : l'app a finalement tranché « Bounce » (cf. changelog « Karma & Bounce »), contre la reco de Gemini.**

## Note (matter vs material)
**matter** = matière physique fondamentale (indénombrable) ; **material** = matière dont une chose est faite (dénombrable). Le brief de génération d'image final utilise « the pebble's matter will be grey and eroded ».

# DIGEST 2 — DÉCISIONS TECH

## A. Bootstrap de l'app mobile (22 fév.)
Point de départ : « I only know flutterflow, what are the other options? »
- **FlutterFlow** — « gold standard » du dev visuel Flutter, mais cher pour publier (Pro ~70–80 $/mois). Export code (Flutter). « Si vous aimez designer chaque pixel : restez sur FlutterFlow. »
- **Low-code** : Draftbit (React Native, ~29 $), Adalo (~36 $), **Bravo Studio** (Figma → app, ~22 $, recommandé pour « designer first »), Nowa (Flutter, ~30 $). **Éviter Glide** (PWA, galère App Store).
- **Pro Bootstrapper (~0 $)** : **React Native + Expo** (« favori de l'industrie… retire la douleur de RN, pas de Mac requis au début ») ; **Flutter (code)**. Backend Supabase/Firebase.
- **AI-Native** : Lovable/Bolt.new, **Emergent** (apps prod depuis prompts).
- **Bubble** (« logic-first heavyweight ») — Native Mobile Builder récent. **Lock-in majeur : pas d'export de code.** Pour « système métier complexe » (le prochain Airbnb).
- **Replit** (« AI-speed disruptor ») — Agent for Mobile, on **chatte**, utilise **Expo** sous le capot, QR code de test instantané. « De l'idée à l'App Store en 48 h » mais « vibe coding », pas pixel-perfect. « Si vous voulez que l'IA fasse le gros du travail : Replit. »
- **Emergent** (« architect platform ») — full-stack AI-native. *« FlutterFlow se concentre sur l'UI, Replit sur le Code, Emergent sur le **Système** (frontend + backend + doc API cohérents). »* Pour un « SaaS sérieux ».
- **Coûts gatekeeper** : Apple Developer 99 $/an, Google Play 25 $ one-time, backend free tier.
- **Conclusion** : pas de choix tranché par Gemini ; pour le profil d'Alexis (designer, à l'aise data/SQL/front, débutant backend), **Expo/React Native** et **Replit (qui utilise Expo)** convergent ; **Bubble déconseillé** (lock-in).

## B. Génération d'images / le futur « pebble engine »
### Comment Duolingo génère ses « Share Cards » — « Dynamic Asset Generation »
1. **View-to-Bitmap (natif, le plus courant)** : rendre une « vue » invisible (fond + texte dynamique + icônes) en image (PNG/Bitmap) côté device.
2. **Canvas graphiques (Skia, etc.)** : le code dessine (« rectangle arrondi blanc », « place flamme.png ») ; *« l'image reste nette… car générée mathématiquement. »*
3. **SDK tiers** : Placid, Cloudinary, templates remplis via API.
- Méthode probable Duolingo : **Canvas côté téléphone** (pas serveur, coûts de bande passante) ; injection de `streak_count` dans une zone de texte (police Feather).

### Format SVG / vectorisation
*« Pour une image parfaitement nette… ils utilisent souvent le SVG… code XML « aplati » en PNG/JPEG juste au moment de "Partager". »*

### Architecture « Design System » de rendu (le plus transposable)
*« Leurs illustrateurs ne dessinent pas chaque image. Ils créent des **bibliothèques de composants**… Le code assemble ces morceaux comme des **LEGO** selon votre réussite. »* Avantages : pas d'UI inutile, format instantané (carré/vertical), **localisation** (texte traduit sans refaire l'image).

### Côté serveur (fil Supabase)
**Edge Functions** rendant une web view en image ; en Node : **`canvas`**, **`puppeteer`**, + **Cloudinary**. Compromis client (device) vs serveur (bande passante).

### Application concrète au pebble engine (« Gem to generate petroglyph illustration », 26 fév.)
Un galet composé **paramétriquement** depuis un souvenir :
- **Intensity (Medium)** → taille moyenne + forme triangulaire 3 angles arrondis.
- **Valence (Neutral)** → « the pebble's matter will be grey and eroded ».
- **Retro (No)** → pas de fossile d'ammonite.
- **Emotions (Fear, Sadness)** → jusqu'à 2 **veines** (violet = peur, bleu = tristesse).
- **Glyph (Cat)** → zone carrée libre pour un symbole de chat géométrique (flat).
→ Transposition directe du « design system assemblé comme des LEGO » de Duolingo. Style cible défini en amont (flat lay macro, fond noir, pierre rugueuse érodée, glyphe gravé, néo-primitive/pétroglyphe).
