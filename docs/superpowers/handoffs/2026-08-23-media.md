## Verified facts — do not re-derive these, and do not assume otherwise

- **`POST /api/upload` already exists** (`app/api/upload/route.ts`). Bearer-gated on `INBOX_TOKENS`,
  takes `multipart/form-data` with a `file` field, returns a `MediaImage` (201) or `{error}` (400/401/502).
- **`lib/storage.ts` is done and tested**: `uploadImage(bytes, filename) → MediaImage` via Cloudinary,
  with a pure `toMediaImage()` mapping unit-tested without network. `CLOUDINARY_URL` comes from env.
- **The capture bar has no file input.** `app/admin/page.tsx` — the door exists, nothing knocks on it.
- **There are ZERO `MediaImage` records in the production database.** One `MediaEmbed`, provider `link`.
  Nothing in Ariko has ever created an image. This is why the cover has been deferred twice.
- **Nothing renders media anywhere.** Every `media` hit in the codebase is seed/inbox/promote
  plumbing, not rendering.
- **`lib/embeds.ts` matches hosts by substring** — `host.includes("vimeo.com")`. So
  `vimeo.com.evil.test` detects as `vimeo`. Harmless today because nothing iframes an embed;
  **it becomes a trust signal the moment rendering lands**, which is exactly why B3 pairs the two.
  Harden to `host === h || host.endsWith("." + h)`.
- **The editor already round-trips images correctly** (`Image` is registered in `baseExtensions`,
  `lib/entity-markdown.ts`) — slice 5 fixed a bug where saving deleted them. So B2 unblocks image
  support that is already built and tested but has no data.

## The two halves

**B2 — create images.** Wire `/api/upload` into the capture bar, with UX that lets a capture survive
an upload failure ("media pending"). Then the cover convention that has been deferred twice: a bean's
cover = the first `MediaImage` in its newest published sprout's `media[]` — derived, no new field, no
migration. `components/entity.tsx`'s card is the consumer (compose spec §2.6 explicitly waits on this).

**B3 remainder — render media.** Render `media[]` on the bean page and in the editor, and harden
host-matching in the same slice. Providers in the model: soundcloud, spotify, deezer, ausha, youtube,
vimeo, figma, plus a `link` fallback.

## Open decisions — brainstorm these, do not assume

1. **Does the capture bar stay zero-JS?** `CLAUDE.md` now scopes the rule: *metadata* forms stay
   zero-client-JS; the prose editor is "the one deliberate exception… widening it to any other form is
   a decision, not a convenience." A file input can post multipart to a server action with no script,
   so zero-JS is achievable — but "media pending" UX and upload progress push toward JS. **This is the
   decision that shapes the slice.** Whichever way it goes, `CLAUDE.md` gets amended in the same PR.
2. **Where does the upload happen** — through `/api/upload` (already token-gated, already tested) or a
   new server action calling `uploadImage` directly? The route's own comment says "upload failure never
   costs a seed: inbox and upload are separate calls", which is a design stance worth honouring.
3. **Iframe or link-out for embeds?** Iframing third-party players is the moment provider detection
   becomes a security boundary, and the moment a CSP question appears. Rendering a styled link is the
   conservative option and may be enough for now.
4. **Explicit `cover` field vs derived-only** — deferred twice on YAGNI grounds. With real images
   finally existing, re-decide rather than inherit.

## Traps this codebase will set for you

- **Three implementations of one grammar must agree** — remark (public render), the `marked` tokenizer
  (what the editor writes), `extractRefs` (feeds `/api/graph`). `lib/entity-fixtures.ts` +
  `lib/markdown-conformance.test.ts` hold them together, and every fixture row is asserted
  **schema-valid** against the editor's ProseMirror schema. If media touches the grammar, add rows there.
- **`@tiptap/markdown` silently drops any node its schema cannot represent.** That is how images were
  being deleted on save before slice 5. If you add a node, register it in `baseExtensions` and add a
  round-trip fixture, or it will vanish without a test failing.
- **`lib/editor-mount.test.ts` (jsdom) is the only thing that constructs a real `Editor`.** Static
  checks missed a bug that made the editor fail to mount on every page. Extend it, don't bypass it.
- **`extractRefs` runs on every write and is regex-hot.** It has a ReDoS regression test with a 250ms
  bound and a comment explaining why adversarial input must contain a literal `::entity` (V8 skips the
  pattern otherwise, and a test without it measures 0.0ms while vulnerable).
- **`.env.local` points at the PRODUCTION database.** For hands-on verification, run the dev server with
  `MONGODB_DB=<scratch>` plus throwaway `ADMIN_PASSWORD` / `ADMIN_SESSION_SECRET`, and drop the scratch
  DB afterwards. Never write to `beanstalk`.
- **PRs need a Lab Note** when a user would notice the change (`CLAUDE.md`). Media rendering qualifies.
